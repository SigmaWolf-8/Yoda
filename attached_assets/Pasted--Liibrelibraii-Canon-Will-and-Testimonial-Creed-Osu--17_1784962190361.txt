On the World Wide Web, a boundless, decentralized information space, we needed a uniform way to name everything: documents, images, services, mailboxes, and even abstract concepts. In the GAAP representation, the total identification capacity of a URI is the sum of its debited locational liabilities and its credited nominal equities. CAPVT I: QUID EST URI

A Uniform Resource Identifier is a compact string of characters used to identify a resource. That identification can take two forms: locating the resource by describing its primary access mechanism (e.g., its network location), and naming the resource with a persistent, location-independent label. Because of these two functions, the URI standard partitions the universe into two subsets: URLs (Uniform Resource Locators) and URNs (Uniform Resource Names). Every URL and every URN is a URI; the converse is not necessarily true. Think of URI as the genus, while URL and URN are species. CAPVT II: THE GRAND SYNTAX: ANATOMY OF A URI

The power of a URI lies in its generic, extensible syntax. A URI can be decomposed into five principal components:

\[
URI \coloneqq scheme:authority / path ? query \# fragment \quad\text{(RFC 3986 formal grammar)}
\]

Scheme (required): the protocol or specification to use, e.g., https, mailto, ftp, urn. It ends with a colon. Authority (optional): preceded by a double slash //, it contains the host (domain or IP address) and optionally userinfo and a port number. For example, john@example.com:8080. Path (optional): a hierarchical sequence of segments separated by slashes that identifies the resource within the authority's scope. E.g., /articles/treatise.html. Query (optional): introduced by a question mark ?, it provides non-hierarchical data, often key-value pairs, to refine the resource. E.g., ?lang=en&page=2. Fragment (optional): introduced by a hash #, it points to a secondary resource within the primary one, like an anchor in an HTML document. The grammar is meticulously defined such that each component is easily parsed, and reserved characters (like /, ?, #) have special meaning only when used in their defined contexts. This uniformity ensures that any URI can be parsed by a generic algorithm, regardless of the scheme. Under GAAP, each component is a distinct ledger entry: the scheme is the chart of accounts, the authority is the subledger host, the path is the account tree, the query is a filter dimension, and the fragment a note reference.

Let the scheme be a Business Service code, the authority a BIC (ISO 9362), the path a structured remittance line, the query conditional parameters, and the fragment a proprietary end-to-end identifier. The algebraic form:

\[
URI = S : A / P ? Q \# F

\[

\[
A = [userinfo@]host[:port] \quad \text{(host validated as BIC11 per ISO 9362)}

\[

\[

The grammar is a context-free production that yields a deterministic finite automaton. The double-entry constraint is that every opening delimiter ( //, ?, #) must be balanced by a closing contextual scope. The URI string length is an asset measured in octets, the unit of account being the ISO/IEC 8859-1 code point, convertible to ISO 10646 with a fixed exchange rate (percent-encoding). CAPVT III: URLS: THE LOCATORS

A URL not only identifies a resource but also tells you how to get it, its primary access mechanism and network location. The most familiar example is the web address: https://www.example.com/path/to/page?search=uri#section2. Here, https is the scheme (HTTP over TLS), www.example.com is the authority, /path/to/page is the path, search=uri is the query, and section2 is the fragment. Other URL schemes include ftp://, mailto:, tel:, and file://. In each case, the scheme implicitly instructs a client (browser, mail user agent) on how to interact with the resource. CAPVT IV: URNS: THE NAMES

When a resource must have a permanent, location-independent identity, a URN is employed. URNs answer what a resource is, not where it currently resides.
